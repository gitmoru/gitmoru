**リポジトリに何が起きたのか、掘って教えてくれるモグラ**

## これは何か

アカウントがひとつ乗っ取られると、組織全体のブランチが数時間で上書きされます。
そのとき知りたいのは 3 つです。

1. **どこがやられたか** - どのリポジトリの、どのブランチか
2. **何が入ったか** - そのファイルが何をするコードなのか
3. **戻せるか** - 攻撃直前のコミットがまだ記録に残っているか

gitmoru は 1 と 3 をやります。2 はやりません。
**代わりに、2 ができる AI に渡せるようにしました。**

<br>

## なぜ判定しないのか

この道具は「侵害されています / 安全です」とは言いません。言うのはこれだけです。

> この時間帯に、これらのファイルがこう変わりました。

理由があります。

検出ルールは **すでに見た攻撃** から作られます。新しい手口は、定義上そこにありません。
ルールが判定を出す作りでは、**ルールが拾えなかった攻撃が「異常なし」として表示されます。**

実際にそうなりました。ファイル名で探していて、別の名前に付いた同じペイロードを見落とし、
画面には「0 件」と出ました。その画面を見て、しばらく安心していました。

だから gitmoru は、何もかからなかったときこう書きます。

```
検出にかかったものはありません。それでも変更された 14 件には目を通してください。
```

<br>

## やらないこと

| やらない | 理由 |
|---|---|
| `git clone` | エディタでフォルダを開いた瞬間に走るペイロードがあります。**ダウンロードした時点で負けです** |
| 対象コードの実行 | lint もビルドもインストールもしません。読んで説明するだけです |
| 外部への通信 | 画面に CSP をかけて、ペイロードに書かれたアドレスへ要求を出すこと自体を不可能にしています |
| トークンの保管 | `gh` から借りるだけで、画面には渡しません |
| エージェントへの書き込み権限 | エージェントは攻撃者が書いた文章を読みます。そこに指示が混ざっている可能性があります |

詳しくは [SAFETY.md](SAFETY.md) にあります。

## はじめかた

[Node 22 以上](https://nodejs.org)、[pnpm](https://pnpm.io)、[GitHub CLI](https://cli.github.com) が必要です。

```bash
git clone https://github.com/gitmoru/gitmoru.git
cd gitmoru
gh auth login
pnpm install
pnpm app
```

組織かリポジトリと期間を入れて `掘る` を押してください。
既定は今日の 0 時から 7 時までです。だいたいこの時間帯に起きます。

インストーラを配らないのは手抜きではありません。この道具はリポジトリへの
アクセス権を使います。署名のない実行ファイルがそれを求める姿は、この道具が
探している攻撃そのものと見分けがつきません。**使う人は、たった今やられた人です。**
その日に渡すべきなのは、読めるソースのほうだと考えています。

トークンは `gh` から借ります。ここでトークンを書き取る場所はありません。

<br>

## 動きかた

```
期間内の push イベントを集める
        ↓
攻撃直前のコミット（payload.before）と現在のツリーを突き合わせる
        ↓
変更されたファイルをルールと無関係にすべて集める      ← ここが成果物
        ↓
検出器が先に見るものに印をつける                      ← 判定ではなく順番
        ↓
人か AI が読んで判断する
        ↓
巻き戻しは人がアプリで押す
```

戻し先は GitHub が覚えているものから来ます。アクティビティは 90 日ほどしか残らないので、
それより古いものは戻せません。それも画面で伝えます。

<br>

## AI に接続する

MCP サーバーが同梱されています。接続すると AI が結果を直接読んで、
疑わしいファイルが何をするコードか説明します。

Claude Code、Codex CLI、Gemini CLI、Claude デスクトップ、Cursor、Windsurf、VS Code に対応しています。
アプリの `AI に接続` を押すと、**このパソコンの実際の設定ファイルの場所**まで表示します。

| ツール | いつ使うか |
|---|---|
| `scan` | 最初に。caseId が返ります |
| `triage` | 何から見るか |
| `list_changes` | 変更されたファイル全件 |
| `diff_file` | 攻撃直前と現在のファイルを比較。**ここで判断が起きます** |
| `read_file` | ファイル全体を読む |
| `check_access` | デプロイキー、Webhook、保留中の招待。期間ではなく現状の点検 |
| `preview_restore` | 何をどこへ戻すことになるか（実行はしません） |
| `share_summary` | チームに貼る要約 |

すべて読み取り専用です。[理由](docs/decisions/0005-mcp-is-read-only.md)

## モル

<img src="docs/assets/mole.svg" alt="モル" width="72" align="left" hspace="16">

マンホールの蓋をかぶったモグラです。画面下の地面を掘りながら進み具合を知らせます。
マウスが止まるとそちらへ掘って移動し、しばらく放っておくと眠ります。

絵はすべて文字列の格子です。CSS で伸び縮みさせるのではなく、
何枚もめくって動かしています。アプリのアイコンも同じ絵から焼いています。

モルは **「安全です」とは言いません。**

<br clear="left">

<br>

## 言語

한국어、English、日本語 に対応しています。初回はシステムの言語に合わせて表示し、
タイトルバーから変更できます。

翻訳ではなく **その言語で書き直しています。** どの言語でも「安全です」とは言いません。

## 作った理由

実際のインシデントを CLI で収拾しながら作りました。
ブランチが 200 を超えると手でコマンドを打つのは無理で、
何より **書き損じたコマンドが静かに「0 件」を返すのが怖かった** からです。

だからこの道具は失敗を隠しません。
確認できなかったものは数えて、目につく場所に書きます。
