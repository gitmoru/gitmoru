# 언어 추가하기

지금 한국어, English, 日本語 를 지원한다. 사전은 `src/i18n/locales/` 에 있다.

## 어떻게 돼 있나

`ko.ts` 가 **타입의 기준**이다. 여기에 키를 더하면 다른 언어 파일에서 타입 오류가 난다.
그게 의도한 것이다. 빠진 문장이 있으면 빌드가 막혀야 한다. 반쯤 번역된 화면이 제일 나쁘다.

숫자가 들어가는 문장은 **함수로** 넣는다.

```ts
changedFiles: (n: number) => `바뀐 파일 ${n}개`,
```

낱말을 조각내서 화면에서 이어붙이지 않는다. 언어마다 어순이 달라서 반드시 어색해진다.
복수형도 함수 안에서 그 언어가 알아서 처리한다. 일본어에는 복수형이 없고, 영어에는 있다.

## 새 언어 추가

1. `src/i18n/locales/ko.ts` 를 복사해 `<code>.ts` 를 만든다
2. 맨 위를 `import type { Dict } from './ko'` / `export const <code>: Dict = {` 로 바꾼다
3. `src/i18n/index.ts` 의 `LOCALES`, `DICTS`, `LOCALE_NAMES` 에 추가한다
4. `pnpm typecheck` 로 빠진 키가 없는지 본다

`LOCALE_NAMES` 에 넣는 이름은 **그 언어로** 쓴다. 못 읽는 말로 적힌 선택지는 고를 수 없다.

## 번역할 때

**옮기지 말고 그 언어로 다시 쓴다.** 한국어판이 "아직 안 팠어요" 라고 해서
영어판이 "Not dug yet" 이 되지는 않는다. 영어권 개발 도구는 그렇게 말하지 않는다.

지킬 것:

- **"안전합니다" 라고 쓰지 않는다.** 어느 언어에서도. 우리가 아는 건 "신호가 안 잡혔다" 이지
  "없다" 가 아니다 ([ADR 0002](../decisions/0002-evidence-not-verdict.md))
- 개발 용어는 그 언어권에서 통용되는 말을 쓴다. 일본어는 가타카나 그대로가 자연스럽다
  (リポジトリ, ブランチ, 強制プッシュ)
- 캐릭터 대사도 그 언어의 도구 말투에 맞춘다. 어린애 말투는 신뢰를 깎는다
- 긴 줄표, 가운뎃점, 말줄임표 대신 `-`, `,`, `...` 를 쓴다

## 어떤 언어로 뜨나

처음에는 `navigator.languages` 를 위에서부터 훑어 아는 말을 고른다. 없으면 English.
사용자가 제목줄에서 바꾸면 그 선택을 기억한다.

## 아직 안 된 것

MCP 서버(`src/mcp/`)의 도구 설명은 아직 한국어다. 사람이 보는 화면이 아니라
에이전트가 읽는 자리라 우선순위를 뒤로 뒀다.
