# 0014. 저장소가 공개로 바뀐 건 신호가 아니라 사건의 사실이다

## 무엇을 정했나

시간대 안에 비공개에서 공개로 바뀐 저장소를 `CaseFile.exposures` 에 담는다.
탐지기를 만들지 않았고, `Finding` 으로도 올리지 않는다.

`verdictOf` 에 `exposed` 를 더했다. 바뀐 파일보다 앞이고, 확인 실패보다는 뒤다.

## 왜 이걸 골랐나

푸시가 하나도 없어도 일어난다. 그게 전부다.

예전 코드에서 그런 시간대는 타임라인이 비어서 `no-activity` 로 접혔다.
화면에는 **"그 시간대엔 아무도 안 건드렸어요"** 가 떴다. 그 사이 저장소는 인터넷에 있다.

[ADR 0002](0002-evidence-not-verdict.md) 가 막으려던 게 정확히 이 화면이다.
규칙이 못 잡은 것이 "이상 없음" 으로 표시되는 자리. 그게 여기 하나 남아 있었다.

값도 이미 치렀다. `listPushEvents` 는 `repos/{repo}/events` 를 받아서
`PushEvent` 만 남기고 나머지를 버리고 있었는데, **버리던 것 안에 `PublicEvent` 가 있었다.**
한 번 받아서 두 갈래로 나누기만 하면 된다. API 왕복이 하나도 안 는다.

## 왜 탐지기가 아닌가

신호는 **바뀐 파일을 정렬하는 형광펜**이다. `repo`, `branch`, `path` 를 들고 다니고,
마지막에 변경 목록의 파일에 붙는다.

저장소가 공개로 바뀐 일에는 파일이 없고 브랜치도 없다. 정렬할 대상도 없다.
그 자체로 서 있는 사실이다. 신호로 만들면 붙을 파일이 없어서 목록에 안 뜨고,
탐지기를 끄면 사실이 사라진다. **사실은 설정으로 끌 수 있으면 안 된다.**

## 왜 바뀐 파일보다 앞인가

파일은 되돌리면 없던 일이 된다. 밖으로 나간 것은 안 그렇다.
누가 언제 복제했는지 확인할 방법이 없어서, 받는 사람이 할 일이 아예 다르다.
되돌리기가 아니라 **키와 토큰을 새로 발급하는 일**이 된다.

확인 실패보다는 뒤다. 못 판 곳이 있는데 `exposed` 로 접으면
"공개된 건 이 하나" 로 읽힌다. 더 있을 수 있다.

## 안 본 것과 0건을 가른다

`exposures` 는 선택 필드다. `undefined` 와 `[]` 가 다른 뜻이다.

| 값 | 뜻 |
|---|---|
| `undefined` | 이 사건을 훑을 때는 안 봤다. 이 검사가 생기기 전 기록이다 |
| `[]` | 봤는데 없었다 |

되짚어 채울 방법이 없다. 이벤트 API 는 90일까지만 남고, 그 사건이 언제 것인지도 모른다.
그래서 v1 을 v2 로 옮길 때처럼 조용히 `[]` 를 넣지 않는다. 그건 안 본 것을 확인한 것으로 만든다
(SAFETY.md 11번). `summarize().exposed` 가 `null` 을 그대로 내보내고, `open_case` 는 그걸 말한다.

## 하지 않기로 한 것

**이름으로 찾지 않는다.** 지금 도는 웜은 특정 이름의 저장소를 만든다.
그 이름을 넣으면 다음 판에서 0건이 뜬다. [ADR 0008](0008-detectors-never-judge-by-filename.md)
에서 한 번 겪었고, 그때 화면의 0 을 보고 한동안 안심했다.
우리가 잡는 건 이름이 아니라 **"비공개였던 것이 이 시간대에 공개로 바뀌었다"** 는 사실이다.

**판정하지 않는다.** 정당하게 오픈소스로 푼 저장소도 여기 걸린다.
그래도 문장은 안 바뀐다. 공개로 바뀐 것은 어느 쪽이든 사실이다.

## 이걸로 못 잡는 것

적어둔다. 안 적으면 이 검사가 다 잡아준다고 믿게 된다.

- **공격자가 처음부터 공개로 만든 저장소.** `CreateEvent` 라서 `PublicEvent` 가 안 뜬다
- **개인 계정으로 옮겨간 저장소.** 훑는 조직 밖이라 목록에 아예 안 들어온다.
  지금 도는 웜이 실제로 하는 게 이거다
- **90일 넘은 사고.** 이벤트가 안 남아 있다
