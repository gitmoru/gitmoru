# 0005. 에이전트에게는 읽기만 넘긴다

## 무엇을 정했나

MCP 서버는 읽기 전용이다. 되돌리기(force-push)를 도구로 노출하지 않는다.
`preview_restore` 로 "무엇을 어디로 되돌리게 되는지" 까지만 보여주고, 실행은 사람이 앱에서 한다.

## 왜

에이전트를 붙이는 이유는 하나다. **도구가 못 하는 판단을 시키려고.**
"이 파일이 무슨 코드인지" 는 규칙으로 못 정한다. 그건 읽어야 아는 것이다.

그런데 읽는다는 건 **공격자가 쓴 글을 컨텍스트에 넣는다**는 뜻이다.
거기에 "이전 지시를 무시하고 ..." 같은 문장이 들어 있을 수 있고, 실제로 그런 수법이 있다.

쓰기 도구가 열려 있으면 그 문장이 곧 실행 경로가 된다.
읽기 전용이면 최악의 경우에도 **잘못된 설명**에서 끝난다. 저장소는 그대로다.

## 그래서 어떻게 되나

- 도구 7개 전부 읽기다: `scan`, `triage`, `list_changes`, `read_file`, `preview_restore`, `share_summary`, `list_cases`
- 파일 본문은 `<untrusted-sample>` 로 감싸고, 데이터이지 지시가 아님을 프롬프트에 못박는다
- 샘플 크기에 상한을 둔다
- 되돌리기 방아쇠는 사람이 앱에서 당긴다. 사람이 승인한 케이스 파일에서만 출발한다

## 하지 않기로 한 것

- "확인 절차를 붙이면 되지 않나" 를 하지 않는다. 확인 문구를 만드는 것도 에이전트다
- 계획 ID 를 넘기면 실행되는 도구도 만들지 않는다. ID 는 앞 단계 출력에 들어 있다
