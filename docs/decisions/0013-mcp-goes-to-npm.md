# 0013. MCP 서버는 npm 에 올리고, 앱은 클론으로 둔다

## 무엇을 정했나

`gitmoru` 를 npm 에 공개한다. 두 가지가 명령 한 줄로 된다.

```bash
npx -y gitmoru        화면을 브라우저로 연다
npx -y gitmoru mcp    MCP 서버를 띄운다
```

**되돌리기는 여전히 Electron 앱에서만** 한다. 저장소를 바꾸는 동작을 명령 한 줄로 열지 않는다.

## 왜

경로를 사람이 채워야 했다.

```bash
claude mcp add gitmoru -- npx tsx <경로>/src/mcp/index.ts
```

`<경로>` 는 클론한 폴더다. 복사 버튼을 눌러도 그대로는 안 돌아간다. 붙이려던 사람 대부분이
여기서 멈춘다. MCP 디렉터리에서도 "설치할 수 없는 서버" 로 표시됐다.

npm 에 올리면 그 자리가 사라진다. 그리고 **웹 모드가 딸려 온다.** Electron 은
개발 의존성이라 `npx gitmoru` 는 그것 없이 브라우저로 화면을 연다.
사고 난 사람이 하는 일이 다섯 줄에서 한 줄로 줄어든다.

## 설치 파일을 안 만들기로 한 것과 충돌하나

[ADR 0006](0006-desktop-app-not-a-browser-tab.md) 와 사이트에 적어둔 이유는 이것이었다.

> 서명 없는 실행 파일이 저장소 접근 권한을 요구하는 모습은,
> 이 도구가 찾아내는 공격과 구분이 안 된다.

`npx` 도 코드를 실행한다. 같지 않지만 완전히 다르지도 않다. 다른 점은 이렇다.

|  | 서명 없는 실행 파일 | npx |
|---|---|---|
| 코드 | 안 보인다 | npm 에서 그대로 읽힌다 |
| 출처 | 브라우저 내려받기 | 알려진 레지스트리 |
| 운영체제 | "개발자를 확인할 수 없음" | 경고 없음 |

**마찰을 낮추는 대가로 "읽고 나서 돌려라" 를 조금 양보한다.** 양보할 만하다고 봤다.
소스가 읽히고, `npx` 는 개발자가 매일 쓰는 도구고, 클론 경로는 그대로 남는다.

## 그래서 어떻게 되나

- MCP 진입점을 한 파일로 굽는다 (`scripts/build-mcp.mjs`). 받는 쪽에 `tsx` 도 소스 트리도 필요 없다
- `files` 를 정해서 올라갈 것만 올린다. 소스와 스크린샷은 안 올라간다
- `react`, `react-dom`, `motion` 을 개발 의존성으로 옮긴다. 이미 `dist` 에 구워져 있어서
  받는 사람이 또 받을 이유가 없다. 런타임 의존성은 MCP SDK 와 zod 둘뿐이다
- 앱의 `AI 붙이기` 화면과 사이트의 명령을 전부 `npx -y gitmoru mcp` 로 바꾼다

## 하지 않기로 한 것

**되돌리기를 명령으로 열지 않는다.** `npx gitmoru restore` 같은 건 만들지 않는다.
force push 는 되돌릴 수 없고, 그 방아쇠는 사람이 화면을 보고 당겨야 한다
([ADR 0005](0005-mcp-is-read-only.md), SAFETY.md 10번).

**Electron 앱을 npm 으로 배포하지 않는다.** Electron 은 100MB 가 넘는 바이너리다.
`npx` 로 그걸 받게 하는 건 설치 파일을 다른 이름으로 부르는 것과 같다.
