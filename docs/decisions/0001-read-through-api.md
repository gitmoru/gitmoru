# 0001. 저장소를 내려받지 않고 API 로만 읽는다

## 무엇을 정했나

`git clone`, `git fetch`, `git checkout` 을 쓰지 않는다.
분석에 필요한 모든 것을 GitHub REST API 로 가져오고, 파일 내용은 메모리에만 둔다.

## 왜

이 도구가 보는 저장소는 **이미 감염됐을 수 있는 저장소**다.
실제 사고에서 확인된 감염 경로가 이렇다.

- `.vscode/tasks.json` + `.vscode/settings.json` → **폴더를 편집기로 여는 순간** 자동 실행
- `eslint.config.js`, `postcss.config.js` 끝에 붙은 페이로드 → **린트, 빌드, 커밋만 해도** 실행

즉 **clone 하는 순간 이미 진 것**이다. 파일이 디스크에 놓이면 그 뒤는 우리 통제 밖이다.
편집기, 파일 감시자, 백신, 인덱서 같은 것들이 우리 허락 없이 그 파일을 건드린다.

## 그래서 어떻게 되나

- 브랜치 비교는 커밋 트리끼리 맞춰본다 (`GET /git/trees?recursive=1`)
- 파일 내용은 필요할 때 한 개씩 가져온다 (`GET /contents/{path}`)
- 큰 저장소에서는 API 호출 수가 늘어난다. 이건 감수한다
- `truncated` 응답은 **오류로 취급한다.** 잘린 목록을 전체로 착각하면 안 된다

## 하지 않기로 한 것

- 속도를 위한 얕은 클론(`--depth=1`)도 하지 않는다. 얕아도 파일은 디스크에 놓인다
- 임시 폴더에 내려받고 지우는 것도 하지 않는다. 지우기 전에 이미 늦는다
