# 0012. 사건 기록은 디스크에 남긴다

## 무엇을 정했나

훑기가 끝나면 사건 기록을 `~/.gitmoru/cases/<id>.json` 에 **자동으로** 저장한다.

- 저장 버튼을 두지 않는다. 훑는 즉시 남는다
- 앱과 MCP 서버가 같은 폴더를 본다
- 오래됐다고 우리가 알아서 지우지 않는다

## 왜

원래는 메모리에만 있었다. 창을 닫으면 조사한 게 전부 사라졌다.

그게 그냥 불편한 정도가 아니었던 이유는, **GitHub 활동 기록이 90일까지만 남기 때문**이다.
그 안에 다시 안 열어보면 이벤트가 만료돼서 같은 시간대를 다시 훑을 수조차 없다.

```
새벽에 조사 -> 창 닫음 -> 기록 날아감
   -> 몇 달 뒤 다시 보려니 이벤트도 만료
   -> 영구 소실. 다시 만들 방법이 없음
```

사고 조사 도구에서 이건 기능이 아니라 구멍이다.
사람이 제일 지쳐 있는 시각에, 제일 되돌릴 수 없는 방식으로 증거가 사라진다.

저장 버튼을 안 두는 것도 같은 이유다. **사고 한복판에서 "저장 눌렀나?" 를 기억하라는 건
안 되는 요구다.** 기억해야 지켜지는 안전장치는 언젠가 샌다.

## SAFETY.md 와 충돌하지 않는 이유

2번은 **저장소 내용**을 디스크에 쓰지 말라는 것이다. 여기서 쓰는 건 우리가 만든 요약이다.

8번이 이미 케이스 파일(JSON)을 내보내도 되는 유일한 것으로 정해뒀고,
거기에 **페이로드 원문을 넣지 않는다**는 것도 같이 못박아 뒀다.
경로, 크기, 해시, 근거만 들어간다. 그래서 이 파일을 디스크에 둬도
내 컴퓨터에 악성 코드를 남기는 게 아니다.

원문이 필요하면 그때 API 로 다시 가져온다. 그 원칙은 그대로다.

## 그래서 어떻게 되나

**앱과 에이전트가 조사를 공유한다.** 전에는 각자 따로 훑어서 같은 일을 두 번 했다.

```
사람이 앱에서 훑음
   -> Claude Code 에서 list_cases
   -> 다시 안 훑고 그 caseId 로 바로 물어봄
```

Electron 의 `userData` 를 안 쓴 게 이것 때문이다. MCP 서버는 Electron 이 아니라
그 경로를 알아낼 수 없다. 양쪽이 계산할 수 있는 곳에 둬야 같은 폴더를 본다.

## 하지 않기로 한 것

**오래된 기록 자동 삭제.** 사고 기록을 도구가 임의로 없애면 그게 곧 증거 인멸이고,
무엇이 사라졌는지도 아무도 모른다. 지우는 건 사람이 한다.

**못 읽은 파일 건너뛰기.** 깨진 파일은 목록에서 빼지 않고 몇 개인지 같이 알린다.
목록에서 사라지면 사람은 그게 원래 없었다고 읽는다 ([ADR 0009](0009-failure-is-its-own-state.md)).

**암호화.** 페이로드가 안 들어가는 요약이고, 이미 사용자 홈에 있다.
암호를 걸면 사고 한복판에 열쇠 문제가 하나 더 생긴다. 얻는 것보다 잃는 게 크다.
