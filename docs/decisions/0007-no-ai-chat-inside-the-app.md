# 0007. 앱 안에 AI 채팅을 넣지 않는다

## 무엇을 정했나

지금은 앱 안에서 바로 AI 에게 물어보는 채팅창을 만들지 않는다.
대신 MCP 로 붙여서, 사용자가 이미 쓰는 도구에서 물어보게 한다.

**이건 기술적으로 못 해서가 아니다.** 넣으려면 넣을 수 있다. 방법도 여러 가지다.

## 넣는다면 어떤 방법이 있나

| 방법 | 어떻게 | 걸리는 것 |
|---|---|---|
| 사용자 API 키 | 사용자가 자기 키를 넣는다 | 우리가 키를 다루게 된다. 그리고 사용자가 요금을 따로 낸다 |
| 로컬 CLI 재사용 | 이미 설치된 에이전트 CLI 를 프로세스로 부른다 | 새 계정이 필요 없다. 그 CLI 가 깔려 있어야 한다 |
| 우리 서버 경유 | 우리가 키를 들고 중계한다 | **파일 내용이 우리 서버를 지나간다** |
| 로컬 모델 | 이 컴퓨터에서 도는 모델에 물어본다 | 성능이 아직 부족하다. 대신 아무것도 안 나간다 |

"편집기처럼 계정으로 로그인해서 쓰면 되지 않나" 는 자연스러운 물음이다.
그건 그 회사가 자기 제품을 위해 만든 로그인이다. 제3자 앱이 남의 구독을 대신 쓰는
공개된 길은 지금 없다. 그래서 3번(우리 서버 경유)이 아니면 결국 1번이나 2번이 된다.

## 왜 지금은 안 하나

이 앱이 사용자에게 하는 약속이 하나 있다.

> 이 컴퓨터 밖으로 안 나가요.

우리가 새 통로를 뚫으면 그 약속이 깨진다. 편의는 얻지만, 그 편의가 이 도구를 쓰는 이유를 없앤다.
"조사 도구인데 조사 대상을 어디론가 보낸다" 는 앞뒤가 안 맞는다.

MCP 로 붙이면 나가는 건 맞다. 하지만 **사용자가 이미 그렇게 쓰기로 한 도구로** 나간다.
우리가 통로를 뚫는 것과, 있는 통로에 얹는 것은 다르다.

## 넣게 된다면 지킬 것

배포해서 여러 사람이 쓰게 되면 이 결정은 다시 볼 수 있다. 그때도 아래는 그대로다.

- **기본은 꺼짐.** 켜는 건 사용자가 한다
- 켜기 전에 **무엇이 나가는지** 파일 이름 단위로 보여준다
- 켜져 있는 동안 화면에 계속 표시한다. 한 번 동의하고 잊게 만들지 않는다
- 어떤 방법을 쓰든 **[ADR 0005](0005-mcp-is-read-only.md) 는 그대로다.**
  앱 안의 AI 에게도 쓰기 도구를 주지 않는다. 그건 개인정보 문제가 아니라 프롬프트 주입 문제라서,
  통로가 안이든 밖이든 똑같이 위험하다

## 그래서 지금 하는 것

붙이는 방법 안내를 잘 만드는 데 공을 들인다 (`ui/panels/ConnectAgent.tsx`).
도구별로 이 컴퓨터의 실제 경로까지 보여주고, 축약 경로를 쓰지 않는다.
