# 0008. 파일 이름만으로 판단하는 탐지기를 만들지 않는다

## 무엇을 정했나

탐지기는 파일 이름을 **단서로는 쓰되 근거로는 쓰지 않는다.**
`.vscode/tasks.json` 이라서 의심한다는 규칙을 추가하지 않는다.

## 왜

조사 중에 실제로 놓쳤다.

`.vscode/tasks.json` 과 특정 폰트 파일명으로 찾고 있었는데,
같은 페이로드가 `eslint.config.js` 끝에도 붙어 있었다. 이름이 다르니 안 걸렸고,
화면에는 "0건" 이 떴다.

이름은 공격자가 언제든 바꾼다. 바꾸는 데 비용이 거의 안 든다.
반면 **크기, 해시, 커밋 메타데이터** 는 공격자가 바꾸기 어렵거나, 바꾸면 다른 흔적이 남는다.

## 그래서 어떻게 되나

지금 있는 탐지기가 무엇을 근거로 삼는지:

| 탐지기 | 근거 | 이름에 의존하나 |
|---|---|---|
| `forged-commit` | author 날짜와 committer 날짜의 차이 | 아니오 |
| `size-jump` | 파일 크기 급증, 새로 생김 | 위험도 설명에만 |
| `shared-blob` | 여러 저장소에 나타난 같은 blob 해시 | 아니오 |
| `tool-marker` | `.gitignore` 에 추가된 작업용 파일 이름 | 내용에 의존 |

`size-jump` 는 어떤 파일이 위험한지 **설명할 때만** 이름을 본다.
"이건 린트할 때 자동으로 읽혀요" 같은 문장이다. 걸러내는 데는 쓰지 않는다.

## 이름으로 알아내도 되는 것

역할은 다르다. `.github/workflows/deploy.yml` 은 **경로 자체가 규격**이다.
GitHub Actions 가 그 자리에 있는 파일을 workflow 로 인식하니, 우리가 같은 규칙을 읽는 것은
추측이 아니다. `core/fileRole.ts` 가 그 일을 한다.

구분은 이렇다.

| | 예 | 되나 |
|---|---|---|
| 이름으로 **악성 여부**를 판단 | "tasks.json 이면 의심" | 안 됨 |
| 이름으로 **역할**을 판단 | ".github/workflows 면 CI 정의" | 됨 |

역할은 걸러내는 데 쓰지 않는다. 바뀐 파일은 전부 목록에 남고, 역할은
"이 중에 자동으로 실행되는 자리가 몇 개" 를 세어 먼저 보이게 할 뿐이다.

## 하지 않기로 한 것

- 확장자 블랙리스트를 만들지 않는다
- "수상한 파일명" 목록을 만들지 않는다
- 역할로 목록을 걸러내지 않는다. 세는 데까지만 쓴다
