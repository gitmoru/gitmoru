# 구조

## 한 장으로

```
        사람이 보는 것                   에이전트가 보는 것
        ┌──────────────┐                ┌──────────────┐
        │   src/ui     │                │   src/mcp    │
        └──────┬───────┘                └──────┬───────┘
               │                               │
               └───────────┬───────────────────┘
                           ▼
                    ┌─────────────┐
                    │  src/core   │   도메인. 화면도 Electron 도 모른다
                    └──────┬──────┘
                           ▼
                  ┌────────────────┐
                  │ src/platform   │   렌더러 ↔ 로컬 프로세스 다리
                  └────────┬───────┘
                           ▼
                  ┌────────────────┐
                  │ server/proxy   │   유일한 바깥 통로
                  └────────┬───────┘
                           ▼
                     api.github.com
```

화살표는 한 방향이다. **`core` 는 `ui` 를 모른다.** 이걸 어기면 MCP 서버가 화면 코드를 끌고 오게 된다.

## 폴더

### `src/core` - 도메인

무엇이 바뀌었는지 알아내는 로직. React 도 Electron 도 여기 없다.

| 파일 | 하는 일 |
|---|---|
| `types.ts` | 이 프로젝트의 낱말. `CaseFile` 이 모든 것의 중심이다 |
| `github.ts` | GitHub 읽기. 쓰기는 `updateRef` 하나뿐 |
| `changes.ts` | 트리끼리 비교해 바뀐 파일을 **규칙과 무관하게 전부** 모은다 |
| `detectors/` | 먼저 볼 것을 위로 올리는 규칙들 |
| `scan.ts` | 위의 것들을 엮는 파이프라인 |
| `restore.ts` | 되돌리기 계획 세우기와 실행 |
| `share.ts` | 팀에 붙여넣을 요약문 |
| `safeText.ts` | 페이로드를 안전하게 다루기 (URL 무력화, 공백 접기, 감싸기) |

### `src/ui` - 화면

| 폴더 | 무엇 |
|---|---|
| `chrome/` | 창 틀. 제목줄, 상태줄, 아래 칸, 첫 화면 |
| `scene/` | 하늘, 땅, 모루. 도트로 된 모든 것 |
| `panels/` | 일하는 화면. 설정, 상세, 변경 목록, 되돌리기, AI 붙이기 |
| `fields/` | 입력 요소. 브라우저 기본 위젯을 쓰지 않고 직접 만든다 |
| `hooks/` | 화면 상태를 묶어둔 것 |
| `brand/` | 로고 |

### `src/mcp` - 에이전트용

| 파일 | 무엇 |
|---|---|
| `index.ts` | 시작점. 전송 연결과 도구 등록만 |
| `context.ts` | 도구들이 함께 쓰는 것 (GitHub 클라이언트, 사건 보관소, 응답 헬퍼) |
| `tools/*.ts` | 도구 하나당 파일 하나. `register~(server, ctx)` 를 내보낸다 |

### 그 밖

| 위치 | 무엇 |
|---|---|
| `src/platform/bridge.ts` | 화면이 로컬 프로세스에 일을 시키는 통로 |
| `server/proxy.mjs` | 바깥으로 나가는 유일한 문. 호스트 고정, 쓰기 화이트리스트 |
| `electron/` | 창 만들기, IPC, CSP 적용 |
| `bin/gitmoru.js` | 브라우저 모드 진입점 |
| `scripts/` | 아이콘 굽기, 개발 실행, MCP 두드려보기 |

## 지키는 것

**한 방향 의존.** `ui` → `core` → `platform` → `server`.
`core` 안에서 `../ui` 를 import 하는 코드는 리뷰에서 막는다.

**도트 그리기는 한 곳.** `ui/scene/PixelArt.tsx` 만 도트를 SVG 로 그린다.
예전에는 파일마다 같은 이중 반복문이 있었는데, 그러면 `shapeRendering` 하나 빠뜨린 곳만
뿌옇게 나오고 원인을 찾기 어렵다.

**파일 길이.** 300줄을 넘으면 쪼갤 자리를 찾는다. 줄 수 자체가 문제는 아니고,
한 파일이 여러 일을 하고 있다는 신호로 본다.

**주석은 왜를 적는다.** 무엇을 하는지는 코드가 말한다.
그렇게 한 이유, 특히 **다르게 했다가 겪은 일**을 적는다.
